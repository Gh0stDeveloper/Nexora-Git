# Nexora Git Download Website

> [Documentation hub](README.md) · [VPS installer](VPS_INSTALLER.md) · [Command reference](NEXORA_GIT_COMMANDS.md) · [Release process](RELEASE_PROCESS.md)

Nexora Git includes an official self-hosted website for project information and direct distribution of the latest signed Android APK.

The website is intentionally part of the same repository and VPS lifecycle as the Android app and Auth Broker. A normal installation provisions it automatically, and future `nexora-git update` runs update it when website source changes.

## Technology

The website uses:

- Next.js 16 App Router;
- TypeScript;
- React 19;
- Tailwind CSS 4;
- Node.js 24 LTS inside the production container;
- Docker Compose;
- Nginx as the public TLS reverse proxy.

The website is built with Next.js `output: "standalone"`, so the runtime image contains only the production server and required assets.

## Public routes

The website and Auth Broker intentionally share one managed HTTPS domain.

Nginx routes requests by path:

| Route | Destination |
| --- | --- |
| `/`, `/terms`, `/robots.txt`, `/sitemap.xml`, social metadata routes | Next.js website |
| `/api/health` | Next.js website health endpoint |
| `/download/nexora-git.apk` | latest published signed APK, served directly by Nginx |
| `/health` | Auth Broker health endpoint |
| `/oauth/callback` | Auth Broker OAuth callback |
| `/v1/oauth/*` | Auth Broker confidential API |

This routing preserves the Android authentication contract while allowing the normal domain root to serve the download website.

## Container isolation

The Auth Broker and website are separate containers.

The website container:

- runs as an unprivileged `nexora` user;
- uses a read-only root filesystem;
- drops all Linux capabilities;
- enables `no-new-privileges`;
- receives the public site URL;
- mounts only the public release directory as read-only;
- never receives the Android keystore;
- never receives signing passwords;
- never receives the GitHub App Client Secret.

The Auth Broker continues to own confidential OAuth exchange credentials.

## Signed APK publication

The Android build worker remains unprivileged and does not receive release signing credentials.

A release lifecycle is:

```text
background Gradle build
        ↓
unsigned APK/AAB staging
        ↓
nexora-git android sign BUILD_ID
        ↓
signature + certificate verification
        ↓
public APK publication
        ↓
website download button
```

After `android sign` verifies the signed APK/AAB against the persistent Signing Vault, the APK is copied into:

```text
/var/lib/nexora-git/web/releases/BUILD_ID/Nexora-Git.apk
```

Public metadata is stored alongside it as `latest.json`.

An atomic `current` symlink points to the current public release:

```text
/var/lib/nexora-git/web/releases/current
```

The website reads:

```text
/releases/current/latest.json
```

inside its read-only Docker volume.

### Public metadata

The release metadata contains only:

- version name;
- version code;
- build job ID;
- source commit;
- signing timestamp;
- APK SHA-256;
- APK size;
- public download URL.

No signing secret or broker secret is copied into the website release directory.

### Public release retention

The publication layer keeps a small number of recent signed website releases. The current release is never deleted by the website retention pass.

This is independent from the Android build-artifact retention policy.

## Download behavior

The public download URL is:

```text
https://DOMAIN/download/nexora-git.apk
```

Nginx serves the APK directly with:

- Android APK content type;
- attachment filename `Nexora-Git.apk`;
- `no-store` cache policy;
- `X-Content-Type-Options: nosniff`.

Until a signed APK has been published, the website renders an explicit **APK not published yet** state instead of linking to an unsigned or nonexistent artifact.

## Installation

The standard VPS installer installs the website automatically.

It:

1. reuses Docker if already installed;
2. allocates a free loopback web port;
3. stores `WEB_PORT` and `SITE_URL` in the protected Compose environment;
4. builds the Next.js production image;
5. starts Auth Broker and website containers;
6. configures split Nginx routing;
7. validates local website health;
8. validates public HTTPS website health.

No system-wide Node.js/npm installation is required on the VPS.

## Updates

`nexora-git update` compares the previous and new Git commits.

The website image is rebuilt only when:

- files under `web/` changed; or
- the Docker Compose definition affecting the website changed; or
- no existing website image is available.

If the website source did not change and its image already exists, the update reuses the cached image and does not reinstall npm dependencies.

Docker's layer cache also means normal source-only website changes reuse the dependency layer when `package.json` and the lockfile have not changed.

### Existing VPS migration

A VPS installed before the website feature may receive the new repository files during its first update while the already-running old updater still has the previous runtime logic loaded.

After that first update, run:

```bash
sudo nexora-git update
```

one additional time. The new no-op update path detects that the website runtime has not yet been provisioned, creates its configuration, starts the container and installs the new Nginx routing without requiring another source revision.

A fresh install or `nexora-git reconfigure` does not need this one-time migration step.

## Operations

### Status

```bash
sudo nexora-git web status
```

Shows the public website URL, local port, container state, health and currently published APK job.

### Diagnostics

```bash
sudo nexora-git web doctor
```

Checks local/public health, Nginx route partitioning and public APK consistency.

### Force deployment

```bash
sudo nexora-git web deploy
```

Forces a fresh website image build from the current repository, starts the service, refreshes Nginx and requires public health to pass.

### Restart

```bash
sudo nexora-git web restart
```

Restarts only the website container and requires local health recovery.

### Logs

```bash
sudo nexora-git web logs
```

Follows the website container logs.
